# Xiaomi → клиент на эмуляторе — 2 ноября 2026

## Итог после перехода на WHPX: PASS, 2 из 2 прогонов

Сервер — физический Xiaomi 12T Pro, Android 15 / API 35. Клиент — один
Pixel_10, Android 17 / API 37, x86_64, страницы 16 КБ. Emulator 37.2.13
подтвердил `WHPX(10.0.26300) is installed and usable`; HypervisorPresent=True.
Использовались 4 ГБ RAM, 2 vCPU, SwiftShader, без аудио, Vulkan и снимков состояния.

Передача шла по локальному адресу Xiaomi `192.168.0.193:8765`, через NAT
эмулятора. ADB/USB использовались для управления и запуска теста;
проброс портов ADB, внешний STUN/TURN и медиаретрансляция не использовались.

| Реализация камеры на Xiaomi | Прогон | Кадры до обрыва / в конце | Возврат новых кадров после включения Wi-Fi | FPS в конце |
| --- | --- | --- | --- | --- |
| Camera2 | PASS, 34,955 с | 301 / 594 | 6042 мс | 30 |
| Camera NDK | PASS, 34,001 с | 299 / 596 | 5563 мс | 30 |

Каждый прогон проверяет не менее 15 первых декодированных кадров, затем
10 секунд непрерывного поступления кадров. Wi-Fi клиента выключается примерно
на 4 секунды; после первой секунды счётчик должен оставаться неизменным ещё
3 секунды. После возврата Wi-Fi требуется новый кадр и ещё 10 секунд
непрерывного видео. Реальный Compose-экран использует SurfaceViewRenderer;
его логи подтверждают отображение примерно 30 FPS, а во время обрыва — 0 FPS.
Повторный выбор сервера и ввод кода после обрыва не требовались.

### Обнаруженное условие: VPN на сервере

При включённом VPN Xiaomi сигналинг проходил, но за 60 секунд кадры не
появлялись. Логи ICE показывали серверные VPN/loopback-кандидаты вместо Wi-Fi
адреса. VPN был помечен `bypassable=false`. После того как пользователь
отключил VPN, обе реализации прошли тест. Текущая версия не обеспечивает
работу через такую VPN-конфигурацию; поддержка VPN требует отдельного решения.

Исправления тестового кода: явно задан возвращаемый тип Unit для JUnit;
обрыв проверяется по остановке кадров, поскольку эмулятор может продолжать
сообщать о виртуальном Ethernet; восстановление требует изменения счётчика
относительно момента обрыва. Подробное логирование WebRTC включается только
через `-e webrtcDiagnostics true`. Тест допускает сетевую инъекцию только на
эмуляторе. Продуктовый код ради этих двух прогонов не менялся.

### Завершение и границы проверки

Камера остановлена кнопкой приложения, dumpsys подтверждает отсутствие
StreamingService. Единственный эмулятор штатно закрыт; процессов QEMU/emulator
не осталось. Помощник Android CLI остановлен. VPN далее управляет пользователь:
до его уточнения был включён общий переключатель, соединение туннеля не
подтверждалось. Свободное место на C: после завершения — около 12,6 ГиБ.

Логи: `xiaomi-to-emulator-camera2-final.log`, `xiaomi-to-emulator-ndk-final.log`,
`remote-frame-metrics.log`, `remote-renderer-metrics.log` в этой папке.
Сборка итогового тестового APK и `git diff --check` прошли.
Проверены один физический сервер и один эмулятор-клиент. NSD между устройствами,
5 отдельных устройств, Android 13, сервер на Android 17, задержка camera-to-screen
и длительная тепловая нагрузка этим прогоном не проверялись. Кадры камеры и
снимки частного окружения не сохранялись.

## История первоначальной диагностики до успешных прогонов

Ниже сохранены результаты этапа до включения WHPX и ручной перезагрузки.
На том этапе эмулятор не доходил до рабочего ADB и межустройственный тест
ещё не выполнялся. Этот первоначальный блокер затем устранён, как описано выше.

### Что было подтверждено до перехода на WHPX

- Xiaomi 12T Pro, Android 15 / API 35, подключён по USB: `a2ce53c4`.
- На Xiaomi запущен Camera2-сервер; интерфейс показывает активную трансляцию
  и 0 клиентов. Его Wi-Fi адрес `192.168.0.193`, порт `8765`.
- TCP-подключение с ПК к этому адресу и порту успешно. Это проверка доступности
  сигналинга, а не доказательство передачи WebRTC-видео.
- Подготовлен и собран `RemoteStreamingTest`: отдельный сервер, реальный
  клиентский ViewModel/Compose-экран, поступление декодированных кадров,
  выключение Wi-Fi клиента и восстановление кадров. Тест не запускает локальную
  камеру на клиенте. В этом прогоне тест не выполнялся.

### Состояние компьютера и первоначальные попытки запуска

После сообщённой пользователем перезагрузки прочитаны события Windows:
Kernel-Power 41 / EventLog 6008 и WHEA-Logger 1 о фатальной аппаратной ошибке
около 02:32 по местному времени. Запись Kernel-Power содержит BugcheckCode=0.
Эти сведения не устанавливают конкретный неисправный компонент или причину
связи с предыдущим запуском эмулятора. AEHD после перезагрузки не использовался.

На момент возобновления было около 7,4 ГиБ свободной физической памяти,
17 ГиБ свободного лимита committed memory; процессов эмулятора и Java не было.

Одновременно запускался максимум один экземпляр. Все попытки после
перезагрузки использовали `-accel off`, программную графику SwiftShader,
`-no-audio`, `-no-snapshot` и отключённый Vulkan.

| Конфигурация | Наблюдение |
| --- | --- |
| Emulator 37.2.13, Pixel_10 / API 37, 16 КБ | Игнорирует RAM 1536 МБ и повышает её до 4096 МБ; Android не загрузился |
| Та же конфигурация, диагностический запуск | QEMU завершился с `0xc0000005`; Event 1000, offset `0x1dd980` |
| Emulator 37.2.13, отдельный AOSP API 36, 1 CPU | То же исключение и offset до загрузки Android |
| Изолированный официальный Emulator 36.2.12, AOSP API 36 | До рабочего ADB не дошёл; процесс завершился |
| Та же версия, программный CPU QEMU `max` | До рабочего ADB не дошёл; процесс завершился |

В первой попытке обработчик Crashpad также завершился с `0x80000003`, оставив
потоки QEMU приостановленными. Приостановленный процесс завершён перед
следующей попыткой. Неподдерживаемый старой версией флаг Crashpad убран;
одна подготовительная попытка завершилась при разборе этого флага.

Версия 36.2.12 загружалась отдельно от SDK из
[официального архива Google](https://developer.android.com/studio/emulator_archive).
SHA-256 архива совпал с опубликованным:
`b0cf63f996d41eb75b0154938ff4a2e0140eab2625b9784cdc9d03ffbb1900df`.
Установленный SDK не заменялся.

Правило обязательных 4 ГБ для API 37 также описано в
[примечаниях Google к Emulator 36.6.11](https://developer.android.com/studio/releases/emulator#36.6.11).

### Подготовка перехода на WHPX

На ПК Intel Core i5-12400; аппаратная виртуализация в firmware включена.
Компонент Windows `HypervisorPlatform` выключен (InstallState=2),
`HypervisorPresent=False`. Следующая альтернатива AEHD — WHPX.
Google рекомендует WHPX на Windows; включение компонента требует перезагрузки:
[инструкция Google](https://developer.android.com/studio/run/emulator-acceleration#vm-windows-whpx).
Первоначально компоненты Windows не менялись. Затем пользователь явно
разрешил включить Windows Hypervisor Platform без перезагрузки.
Административная команда `Enable-WindowsOptionalFeature -Online -FeatureName
HypervisorPlatform -All -NoRestart` завершилась успешно в 02:54 +07:00:
InstallState=1, RestartNeeded=true. Повторная проверка подтвердила включённый
компонент; HypervisorPresent пока False, требуется ручная перезагрузка.
Автоматическая перезагрузка не выполнялась, AEHD не удалялся.

### Проверка оставшихся блокировок и очистка перед перезагрузкой

По предложению пользователя проверены `hardware-qemu.ini.lock` и
`multiinstance.lock` у Pixel_10 и временного LocalStreamClient. При отсутствии
процессов эмулятора они переименованы с суффиксом `.stale-<timestamp>`;
бесхозная запись обнаружения `pid_16288.ini` также переименована.
Повторный запуск после очистки завершился с кодом -1073741819 (`0xc0000005`)
до рабочего ADB. Очистка блокировок сбой не устранила.

Временный отдельный AVD и скачанный Emulator 36.2.12 удалены из проекта.
Оригинальный Pixel_10 и установленный SDK сохранены. Эмуляторы не работают;
свободное место на C: после очистки — около 14,2 ГиБ.
Попытка остановить сервер через shell отклонена: сервис не экспортирован.
До завершения остановки Xiaomi отключился от ADB, поэтому освобождение
камеры не подтверждено; трансляцию можно остановить кнопкой в приложении.

После получения рабочего эмулятора повторить:

```powershell
android install --device=<emulator-serial> --apks=app/build/outputs/apk/debug/app-debug.apk
android install --device=<emulator-serial> --apks=app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
# На API 37 предварительно выдать ACCESS_LOCAL_NETWORK.
adb -s <emulator-serial> shell am instrument -w -e serverHost <Xiaomi-Wi-Fi-IP> -e accessCode <current-code> -e class dev.localstream.RemoteStreamingTest dev.localstream.test/androidx.test.runner.AndroidJUnitRunner
```

Не запускать помощник `android layout` одновременно с инструментальным
тестом на том же устройстве: они используют UiAutomation.
